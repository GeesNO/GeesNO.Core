# GeesNO.Core 0.1.0-preview.1 Release Notes

Status: prepared release notes for a future Developer Preview publication.

These notes are prepared for a future Developer Preview publication. They do
not publish a GitHub Release and do not publish NuGet packages.

## What This Release Is

`0.1.0-preview.1` is the planned first NuGet Developer Preview of
GeesNO.Core Foundation.

It is intended for technical evaluation by developers who want to understand
and experiment with GeesNO.Core's public contracts, capability model, typed
operations, provider manifests, tools, and Runtime facade.

This is not a 1.0 release, not a production certification, and not a formal
conformance program.

## Public Functionality

The preview includes:

- public primitives such as version values, object identifiers, errors, and
  functional results;
- public capability identifiers, exact capability references, descriptors,
  manifests, support declarations, and provider identifiers;
- typed operation and tool contracts;
- the neutral read-only profile:
  - `neutral.echo@1.0.0`
  - `neutral.describe@1.0.0`
  - `neutral.validate@1.0.0`
- system diagnostic contracts for `system.ping@1.0.0`;
- the public Runtime facade:
  - `GeesNORuntimeBuilder`
  - `GeesNORuntime`
  - `ExecutionOptions`
  - `RuntimeCapability`
  - `OperationExecutionResult<TResult>`
  - `OperationExecutionStatus`
  - `GeesNORuntimeConfigurationException`

Runtime internals, Host internals, journal internals, observability internals,
and catalog/invoker internals are not public integration API.

## Integration Model

An integration declares capabilities with a public `CapabilityManifest`,
implements typed tools with `ITool<TOperation,TResult>`, registers those pieces
through `GeesNORuntimeBuilder`, and executes typed operations through
`GeesNORuntime.ExecuteAsync`.

Provider selection may be explicit through `ExecutionOptions`. Implicit
selection is accepted only when exactly one executable provider satisfies the
operation capability.

## Security Posture

The preview is fail-closed / deny-by-default for the current public model:

- unknown or missing capability/provider cases are rejected;
- ambiguous implicit provider selection is rejected;
- unsupported or unavailable capabilities are rejected;
- ordinary unexpected failures are sanitized into public results;
- public errors should expose only stable codes and messages.

The preview does not provide a sandbox for arbitrary third-party code, a
dynamic plugin security model, production security certification, advanced
permissions, or a public vulnerability-response SLA.

Do not report suspected vulnerabilities through public issues or pull requests.
The intended private channel is GitHub Private Vulnerability Reporting /
GitHub Security Advisories after the public repository exists and private
reporting is enabled. That channel is not active yet.

## Compatibility

The packages target .NET `net8.0`.

The local dry-run uses the installed local .NET SDK reported by
`dotnet --version`. The CI workflow requests `.NET 8.0.x`. No `global.json`
is introduced by the dry-run.

## Developer Preview Stability

The package line is pre-1.0:

- public API may evolve before 1.0;
- breaking changes must be documented;
- migration guidance should be provided when relevant;
- package version and capability version are separate concepts;
- a capability version such as `neutral.echo@1.0.0` does not mean package API
  stability at 1.0.
