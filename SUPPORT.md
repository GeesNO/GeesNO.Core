# Support

Status: initial Developer Preview support policy.

GeesNO.Core is in Developer Preview. Support is best effort and has no SLA.

## Bugs

Bugs are defects in documented behavior, build/test workflow, public API
behavior, documentation, samples, or release-preparation material.

After the public repository is available, ordinary bugs may be reported through
the public issue tracker if they do not disclose a security vulnerability. The
bug report issue form is prepared for that workflow, but it is not a security
reporting channel.

## Feature Requests

Feature requests are proposals for new capabilities, APIs, packages, docs,
tooling, adapters, templates, governance, release process, or compatibility
rules.

Developer Preview feature requests are reviewed against the Foundation boundary:
GeesNO.Core must remain headless, vendor-neutral, AI-neutral, software-neutral,
and domain-neutral. The feature request issue form is prepared for that future
public workflow.

## Security Vulnerabilities

Do not report suspected security vulnerabilities through public issues, pull
requests, discussions, or comments.

The intended private disclosure channel is GitHub Private Vulnerability
Reporting / GitHub Security Advisories after the public repository exists and
private vulnerability reporting is enabled. Until that is enabled, the official
private vulnerability channel is a release gate, not an active channel.

See [SECURITY.md](SECURITY.md).

## General Questions

General questions are best-effort Developer Preview discussions. No response
time, support window, compatibility commitment, or production support obligation
is implied.
